The DALI review of the fix passed. It noted that `mergeDirected` still counts opposite legs on one address that start within 5 ms as one leg, where ADR 0011 said opposite directions are never merged. That is kept on purpose and is now stated in ADR 0011: it hides a 1 ms sampling artefact of a constant-level colour swap, and it cannot carry a flash past the limits, because an instant swap is a hard step (one in 2 s) and a faded one takes at least 0.7 s.

The security review of the fix passed: `uniteTimes` keeps every time the old merge kept, so no window counts fewer events. Two follow-ups, neither blocking:
